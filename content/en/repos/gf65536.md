# gf65536 {#gf65536}

[![CI](https://github.com/go-simd/gf65536/actions/workflows/ci.yml/badge.svg)](https://github.com/go-simd/gf65536/actions/workflows/ci.yml)

Region multiply and multiply-accumulate over **GF(2^16)** with the PAR2 /
[`go-erasure/reedsolomon`](https://github.com/go-erasure/reedsolomon) field
(primitive polynomial `0x1100B`, words stored **big-endian**). The kernels were
moved here from reedsolomon, which now imports them. Pure Go, `CGO_ENABLED=0`.
[Repository →](https://github.com/go-simd/gf65536)

## API {#api}

```go
gf65536.MulSlice(dst, src, c)     // dst = src * c
gf65536.MulAddSlice(dst, src, c)  // dst ^= src * c
gf65536.Mul(a, b)                 // one product, table-free
gf65536.Tier()                    // "avx2", "ssse3", "neon", "rvv", ...
```

`dst` must hold at least `len(src)` rounded down to even bytes (it panics
otherwise); an odd trailing byte is ignored; `dst` and `src` may be the same
slice. A little-endian word variant is not provided.

| arch | kernel | notes |
|---|---|---|
| **amd64** | **AVX2** (`VPSHUFB`, 64 B/iter), then **SSSE3** (`PSHUFB`) | runtime dispatch; both tiers run on native CI |
| **arm64** | **NEON** (`VLD2`/`TBL`/`VST2`) | native CI |
| **riscv64** | **RVV** (`vrgather.vv`), gated on `HasV` | QEMU, VLEN=256 |
| **loong64** | **LSX** (`vshuf.b`) | QEMU |
| **ppc64le** | **VSX** (`VPERM`), POWER8 baseline | QEMU power9 and power8 |
| **s390x** | **vector facility** (`VPERM`) | QEMU |
| others | portable Go | the same split tables, no assembly |

## Algorithm {#algorithm}

[GF-Complete](https://web.eecs.utk.edu/~jplank/plank/papers/FAST-2013-GF.html)
SPLIT(16,4): for a fixed coefficient, multiplication is linear over GF(2), so the
product of a 16-bit word is the XOR of eight 16-entry byte tables indexed by its
four nibbles (four for the low result byte, four for the high one). Each kernel
deinterleaves the big-endian words into high and low byte planes, extracts the
nibbles, does the eight byte-shuffle lookups, XORs them and re-interleaves. The
128-byte table is built per call from the coefficient and reused across the
region; sub-block tails use the same tables in Go.

## Performance {#performance}

Measured on GitHub-hosted runners, one core, 1 MiB region, `MulAddSlice`-shaped
workload through reedsolomon's `BenchmarkGalMulAddSIMD`, old and new kernels
interleaved (see the
[reedsolomon pull request](https://github.com/go-erasure/reedsolomon/pull/14)):

| runner CPU | before | after | ratio |
|---|---|---|---|
| Xeon 6975P-C (amd64) | SSSE3, ~10 GB/s | **AVX2, ~20 GB/s** | about 2.0x |
| Neoverse-N2 (arm64) | NEON, ~7.9 GB/s | same NEON kernel, ~7.9 GB/s | 1.00x |

The log-table scalar loop on the same runners: about 1.0 GB/s (amd64) and
0.72 GB/s (arm64). The runs are short (300 iterations); read the ratio, not the
absolute figure. riscv64, loong64, ppc64le and s390x are tested under QEMU and
have no timing here. No comparison with a PAR2 reference tool (par2cmdline,
ISA-L) has been made.

## GFNI {#gfni}

Not implemented. `VGF2P8AFFINEQB` could replace the eight shuffles by four affine
maps over the byte planes, but no GFNI machine was available to check it for
correctness or speed. Tracked in
[go-simd/gf65536#3](https://github.com/go-simd/gf65536/issues/3).

## Testing {#testing}

Exhaustive: all 65536 coefficients against a table-free reference product, all
lengths 0 to 1000, unaligned and in-place regions, guard-page tests that fault on
any access past the slice, and a fuzz target. Each tier is asserted to be the one
selected (`GF65536_WANT_TIER`), including SSSE3 forced on an AVX2 runner.
